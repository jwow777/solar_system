## 1. Общее описание

Интерактивный 3D-симулятор Солнечной системы, реализованный на базе **Three.js** с использованием **TypeScript** и сборщика **Vite**. Проект отображает все 8 планет, карликовые планеты (Плутон, Церера, Хаумеа, Макемаке, Эрида) и 18 спутников с физически корректными орбитами по законам Кеплера.

## 4. Архитектура и модули

### 4.1 `src/main.ts` — Главный модуль
**Роль:** Точка входа приложения, игровой цикл `animate()`.

**Ответственности:**
- Инициализация всех подсистем (`setupScene`, `setupPostProcessing`, `createSolarSystem`, `setupInterface`)
- Физический цикл `updatePhysics(deltaDays)` — обновление позиций планет и спутников
- Управление камерой: плавный переход (`lerpVectors`) к выбранному объекту и слежение за ним
- Таблица периодов вращения `ROTATION_PERIODS` для 13 тел

**Ключевые переменные:**
- `simDays` — счётчик симулированных дней
- `isPaused` — флаг паузы
- `focusTarget` — текущий объект слежения камеры
- `isTransitioning` / `transitionProgress` — анимация перехода камеры

---

### 4.2 `src/setup.ts` — Инициализация сцены
**Роль:** Создание и настройка базовых объектов Three.js.

**Создаёт:**
- `WebGLRenderer` с антиалиасингом, тенями (`PCFSoftShadowMap`), ACES Filmic Tone Mapping
- `PerspectiveCamera` (FOV 45°, позиция `0, 30, 60`)
- `OrbitControls` с демпфированием
- Фон галактики — сфера радиусом 600 единиц с текстурой Млечного Пути (`8k_stars_milky_way.jpg`), загружаемая динамически

---

### 4.3 `src/solarSystem.ts` — Солнечная система
**Роль:** Фабрика всех 3D-объектов сцены.

**Создаёт:**
- **Солнце:** `MeshBasicMaterial` (самосветящееся), `PointLight` (интенсивность 120, дальность 1500), спрайт-ореол через `CanvasTexture` с радиальным градиентом
- **Планеты:** итерация по `PLANETS_DATA`, для каждой — `Group` → `pivot Group` → `Mesh`. Иерархия позволяет независимо вращать планету и двигать группу по орбите
- **Земля:** дополнительные слои — облака (`AdditiveBlending`), атмосфера (кастомный `ShaderMaterial` с Fresnel Rim Light)
- **Кольца Сатурна:** `RingGeometry` с пересчитанными UV-координатами для корректного наложения текстуры
- **Орбитальные линии:** `BufferGeometry` из 180 точек, рассчитанных через `getPlanetPosition`
- **Спутники:** 18 объектов из `MOONS_DATA`, прикреплённых к `group` родительской планеты

**Иерархия объекта планеты:**
```
scene
└── group (позиция = орбитальная позиция)
    └── pivot (вращение вокруг оси)
        └── mesh (геометрия + текстура)
            └── [атмосфера, облака — только для Земли]
```

---

### 4.4 `src/utils/orbitPhysics.ts` — Физика орбит
**Роль:** Реализация законов Кеплера для расчёта позиций планет.

**Данные:** 13 тел Солнечной системы с параметрами J2000.0:
- Большая полуось `a` (а.е.)
- Эксцентриситет `e`
- Наклон орбиты `i` (°)
- Долгота восходящего узла `node` Ω (°)
- Аргумент перигелия `periapsis` ω (°)
- Орбитальный период `period` (сут)
- Средняя долгота на эпоху J2000 `meanLongJ2000` (°)
- Наклон оси вращения `axialTilt` (°)

**Алгоритм `getPlanetPosition`:**
1. Вычисление средней аномалии `M = M₀ + n·t`
2. Решение уравнения Кеплера `E - e·sin(E) = M` методом Ньютона (10 итераций, точность 1e-7)
3. Вычисление истинной аномалии `ν` через `atan2`
4. Вычисление радиус-вектора `r = a(1-e²)/(1+e·cos(ν))`
5. Перевод в 3D-координаты с учётом наклона и узла орбиты
6. Масштабирование: `AU_SCALE = 30` единиц/а.е.

---

### 4.5 `src/utils/orbitMath.ts` — Математика орбит
**Роль:** Вспомогательный модуль для геометрии орбит.

**Экспортирует:**
- `getOrbitPosition(theta, params)` — позиция на эллипсе по параметрическому углу (альтернативный метод, не используется в основном цикле)
- `createOrbitGeometry(params, segments)` — массив точек для `THREE.Line`
- Интерфейс `OrbitParams` (`a`, `e`, `inc`, `node`)

> ⚠️ **Замечание:** Модуль `orbitMath.ts` определяет собственный интерфейс `OrbitParams`, который дублирует часть полей `PlanetOrbitData` из `orbitPhysics.ts`. Функции модуля не используются в основном рендер-цикле — орбитальные линии строятся через `getPlanetPosition` из `orbitPhysics.ts`.

---

### 4.6 `src/moonsData.ts` — Данные спутников
**Роль:** Статические данные о 18 спутниках 4 планет.

| Планета  | Спутники                                                    |
|----------|-------------------------------------------------------------|
| Земля    | Луна                                                        |
| Юпитер   | Ио, Европа, Ганимед, Каллисто (галилеевы)                  |
| Сатурн   | Мимас, Энцелад, Тефия, Диона, Рея, Титан, Япет             |
| Уран     | Миранда, Ариэль, Умбриэль, Титания, Оберон                 |
| Нептун   | Тритон (ретроградная орбита: `period = -5.88`)             |

Каждый спутник: `parent`, `name`, `orbitRadius`, `size`, `period`, `color`, опционально `texture`.

---

### 4.7 `src/postProcessing.ts` — Постобработка
**Роль:** Настройка пайплайна постобработки через `EffectComposer`.

**Проходы:**
1. `RenderPass` — базовый рендер сцены
2. `UnrealBloomPass` — эффект свечения (strength: 0.4, radius: 0.3, threshold: 0.15)

---

### 4.8 `src/interface.ts` — Пользовательский интерфейс
**Роль:** Создание всех UI-элементов управления.

**Компоненты:**

**Левая панель `lil-gui` (320px):**
- 💡 Источник света: мощность, дальность, затухание, фоновый свет, цвет
- 🎨 Экран и эффекты: экспозиция, Bloom (сила/радиус/порог/цвет)
- Переключатель орбит
- Масштаб планет (0.5–2.0)
- ⏱️ Скорость симуляции (0–50 дн/сек)

**Панель управления временем (снизу по центру):**
- Кнопки: ⏮ -10 дней, ⏯ пауза/воспроизведение, ⏭ +10 дней

**Панель навигации (снизу по центру, два ряда):**
- Ряд 1: 11 планет (Солнце + 8 планет + Церера + Плутон)
- Ряд 2: 12 спутников с цветовыми индикаторами
- Клик → плавный перелёт камеры к объекту

**Экспортирует:**
- `params` — реактивный объект настроек
- `TimeControl` — интерфейс управления временем
- `setupInterface()` → `{ setTargetCallback }` — колбэк выбора цели камеры

## 5. Игровой цикл

```
requestAnimationFrame(animate)
    │
    ├── updatePhysics(deltaDays)          // если не на паузе
    │       ├── simDays += deltaDays
    │       ├── для каждой планеты:
    │       │       ├── group.position = getPlanetPosition(data, simDays)
    │       │       └── pivot.rotation.y += угловой шаг (с visualSlowdown=0.05)
    │       └── для каждого спутника:
    │               ├── mesh.position.x = cos(angle) * orbitRadius
    │               └── mesh.position.z = sin(angle) * orbitRadius
    │
    ├── sun.mesh.rotation.y += 0.0005     // вращение Солнца
    │
    ├── обновление камеры:
    │       ├── если isTransitioning: lerpVectors к цели
    │       └── иначе: следование за объектом (delta позиции)
    │
    ├── controls.update()
    └── composer.render()
```

**Скорость симуляции:** `deltaDays = params.timeScale / 60` (при 60 FPS и `timeScale=1` → 1 день/сек реального времени).

## 7. Выявленные проблемы и замечания

### 🔴 Критические

1. **`params.isPaused` не существует** (`src/interface.ts:135`)  
   В обработчике кнопки паузы используется `params.isPaused`, но это поле не объявлено в объекте `params`. Состояние паузы хранится в локальной переменной `isPaused` в `main.ts`. Кнопка не будет корректно переключать иконку.

2. **Отсутствует текстура Плутона** (`src/solarSystem.ts:24`)  
   Импортируется `plutoMap` из `'./img/maps/4k_pluto_fictional.jpg'`, но этого файла нет в папке `src/img/maps/`. Это вызовет ошибку сборки или 404 при загрузке.

### 🟡 Предупреждения

3. **Дублирование `TEXTURE_MAP`** (`src/solarSystem.ts:26-29` и `src/solarSystem.ts:98-102`)  
   Объект `TEXTURE_MAP` объявлен дважды в одном файле — на уровне модуля и внутри функции `createSolarSystem`. Внешний объявление перекрывается внутренним.

4. **Дублирование стилей** (`src/interface.ts:68-117` и `src/index.css`)  
   Стили UI-панелей определены как в CSS-файле, так и инжектируются через `<style>` тег в `interface.ts`. Стили из JS перезапишут CSS-файл, что затрудняет поддержку.

5. **Неиспользуемый модуль `orbitMath.ts`**  
   Функции `getOrbitPosition` и `createOrbitGeometry` не вызываются нигде в проекте. Орбитальные линии строятся через `getPlanetPosition` из `orbitPhysics.ts`.

6. **`any`-типизация в нескольких местах**  
   `setupInterface(system: any, ...)`, `Object.values(system.moons).forEach((moonObj: any) => ...)` — отсутствие строгой типизации снижает безопасность кода.

7. **`postProcessing.ts` без типов параметров**  
   Функция `setupPostProcessing(scene, camera, renderer)` не имеет аннотаций типов TypeScript.

8. **Неиспользуемые текстуры** (5 файлов)  
   `8k_earth_nightmap.jpg`, `8k_earth_normal_map.tif`, `8k_earth_specular_map.tif`, `water_8k.png`, `clouds_8k.jpg`, `4k_venus_atmosphere.jpg` — занимают место, но не подключены.

### 🟢 Рекомендации по улучшению

9. **Ночная сторона Земли**  
   Текстура `8k_earth_nightmap.jpg` уже есть в проекте. Можно реализовать шейдер день/ночь с переходом по направлению к Солнцу.

10. **Нормальная карта Земли**  
    `8k_earth_normal_map.tif` присутствует — можно подключить как `normalMap` вместо `bumpMap` для более качественного рельефа.

11. **Атмосфера Венеры**  
    `4k_venus_atmosphere.jpg` есть в папке — можно добавить слой атмосферы аналогично Земле.

12. **Кэширование позиций**  
    В `animate()` каждый кадр создаётся `new THREE.Vector3()` для `currentWorldPos` и `delta`. Лучше вынести их за пределы цикла.

13. **Типизация системы**  
    Стоит создать интерфейс `SolarSystem` вместо `Record<string, any>` для строгой типизации возвращаемого значения `createSolarSystem`.
