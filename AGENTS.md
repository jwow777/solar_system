# Инструкции для работы с проектом

## Версии и документация

- При каждом изменении версии проекта обязательно обновляй документацию одновременно с кодом. Обновление версии не завершено, пока документация не соответствует фактическому поведению приложения.
- Синхронно меняй версию в package.json и двух полях корневого пакета в package-lock.json. Не меняй версии зависимостей ради версии приложения.
- Для набора совместимых исправлений повышай patch-версию; для новых возможностей и несовместимых изменений выбирай уровень версии по содержанию изменений и указаниям пользователя.
- Добавляй запись в начало CHANGELOG.md с номером версии, датой и понятным списком пользовательских изменений. Не выдавай запланированную работу за выполненную.
- Обновляй текущую версию и инструкции в README.md. Согласовывай ANALYSIS.md с техническими изменениями, проверками и ограничениями; обновляй дату и версию его заголовка.
- Включай изменения документации и версии в тот же коммит, что и соответствующие исправления. Не ограничивай обновление версии одним package.json.

## Проверки

- Выполняй npm run build перед коммитом версии: команда готовит текстуры, проверяет TypeScript, запускает модульные тесты и собирает приложение.
- Для изменений интерфейса выполняй соответствующие браузерные сценарии npm run test:e2e после сборки. Проверяй узкие экраны и сенсорное управление, если они затронуты.
- Указывай только реально выполненные проверки и не скрывай оставшиеся ошибки.
- Сохраняй пользовательские изменения и уже выполненные доработки. Используй относительные пути, чтобы переименование папки не ломало проект.
